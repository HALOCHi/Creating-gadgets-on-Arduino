### ** Занятие 7: OLED-дисплей **

🎯 **Цель занятия:**
Превратить Arduino в мини-компьютер с собственным экраном! Научимся выводить на OLED-дисплей текст, цифры, графики и даже простые рисунки. Поймем, как работает шина I2C, которая позволяет подключать много устройств всего двумя проводами.

---

### 📖 **Теоретическая часть: Магия маленького экрана**


**1. Что такое OLED и чем он круче LCD?**
Представь экран своего телефона. Скорее всего, он OLED.
*   **OLED (Organic Light-Emitting Diode)** — это дисплей, где **каждый пиксель сам светится**. Если пиксель черный — он просто не горит. Поэтому черный цвет на OLED — это идеальный, глубокий черный.
*   **LCD (Liquid Crystal Display)** — это дисплей с **подсветкой**. Даже черный пиксель немного подсвечивается.
*   **Вывод:** OLED дисплеи имеют высокую контрастность, потребляют мало энергии и очень тонкие. Именно такие мы и будем использовать.

    -![oled](https://github.com/user-attachments/assets/ba024bf8-0ae4-419e-b774-dae507a8fffc)

**2. Шина I2C: Разговор по правилам**
К дисплею нужно подвести питание и данные. Данные передаются по специальному протоколу — **I2C (Inter-Integrated Circuit)**.
*   **Как работает:** Представь, что у тебя есть класс, и ты хочешь поговорить с одним учеником. Ты называешь его **адрес** (у каждого устройства на шине I2C он уникален), и начинается разговор. Остальные в это время молчат.
*   **Всего 4 провода:**
    1.  **VCC** — Питание (**3.3V** или **5V**). *Важно: наш OLED часто рассчитан на 3.3V, но обычно работает и от 5V. Но если у тебя есть выбор, лучше 3.3V.*
    2.  **GND** — Земля.
    3.  **SCL (Serial Clock)** — Тактовый сигнал. Это как дирижер, задающий ритм общения. Подключается к **A5** на Arduino Uno/Nano.
    4.  **SDA (Serial Data)** — Линия данных. По этому проводу "бегут" нули и единицы. Подключается к **A4** на Arduino Uno/Nano.

**3. Адрес устройства**
У нашего OLED дисплея есть **адрес по умолчанию**, обычно **0x3C** или **0x3D**. Это как номер квартиры. В коде мы будем указывать этот адрес, чтобы Arduino знал, с кем разговаривать.

**4. Библиотеки — наша суперсила**
Чтобы не писать тысячи строк кода для управления каждым пикселем, мы используем **библиотеку**. Библиотека — это набор готовых функций. Мы будем использовать популярную библиотеку **Adafruit SSD1306** (для управления дисплеем) и **Adafruit GFX** (для рисования графики).

### 🛠 **Практическая часть: Подключаем дисплей и выводим "Hello, World!"**

**📦 Что нужно:**
*   Arduino Uno / Nano
*   Макетная плата
*   OLED-дисплей 128x64 (синий, белый или двухцветный) с интерфейсом I2C
*   Провода «папа-папа»

**🔌 Собираем схему — это очень просто!**
Схема подключения I2C универсальна и проста.

```
        OLED DISPLAY (I2C)                ARDUINO UNO
        ------------------                -----------
        |                |                |         |
        |    GND         |----------------| GND     |
        |    VCC         |----------------| 3.3V*   |
        |    SCL         |----------------| A5 (SCL)|
        |    SDA         |----------------| A4 (SDA)|
        ------------------                -----------
```
*Примечание: Если дисплей не заработал от 3.3V, попробуй подключить VCC к 5V.*

**💻 Шаг 1: Установка библиотек (ВАЖНО!)**
Преподаватель поможет установить библиотеки. Нужно сделать это один раз:
1.  В Arduino IDE: **Скетч -> Подключить библиотеку -> Управлять библиотеками...** (Ctrl+Shift+I).
2.  В поиске введи **"Adafruit SSD1306"**.
3.  Найдите и установите библиотеку **"Adafruit SSD1306 by Adafruit"**.
4.  Она спросит об установке зависимостей — соглашайся, установи и **"Adafruit GFX Library"**.

**💻 Шаг 2: Базовый код — тест дисплея**
Загрузи этот скетч. Он очистит экран, выведет текст разного размера и нарисует круг и прямоугольник.

```cpp
// Подключаем необходимые библиотеки
#include <SPI.h>
#include <Wire.h>
#include <Adafruit_GFX.h>
#include <Adafruit_SSD1306.h>

// Определяем константы для дисплея
#define SCREEN_WIDTH 128   // Ширина дисплея в пикселях
#define SCREEN_HEIGHT 64   // Высота дисплея
#define OLED_RESET    -1   // Если у дисплея нет пина RESET, ставим -1

// Создаём объект дисплея с указанием адреса I2C (обычно 0x3C или 0x3D)
Adafruit_SSD1306 display(SCREEN_WIDTH, SCREEN_HEIGHT, &Wire, OLED_RESET);

void setup() {
  // Инициализируем дисплей с адресом 0x3C
  // Если не работает, попробуй заменить на 0x3D
  if(!display.begin(SSD1306_SWITCHCAPVCC, 0x3C)) {
    Serial.println("Дисплей не найден!");
    while (true); // Бесконечный цикл (стоп), если дисплей не подключен
  }

  // Очищаем буфер дисплея (делаем экран чёрным)
  display.clearDisplay();

  // --- ВЫВОДИМ ТЕКСТ ---
  // Устанавливаем цвет текста (SSD1306_WHITE - белый, SSD1306_BLACK - черный)
  display.setTextColor(SSD1306_WHITE);

  // Устанавливаем размер текста 1 (маленький, 6x8 пикс.)
  display.setTextSize(1);
  // Устанавливаем курсор в позицию (0,0) - верхний левый угол
  display.setCursor(0, 0);
  // Печатаем строку
  display.println("Hello, Arduino!");
  display.println("----------------");

  // Меняем размер текста на 2 (крупнее)
  display.setTextSize(2);
  display.setCursor(0, 20);
  display.println("OLED");
  display.println("Rulez!");

  // --- РИСУЕМ ГЕОМЕТРИЧЕСКИЕ ФИГУРЫ ---
  // Рисуем окружность: (центр_X, центр_Y, радиус, цвет)
  display.drawCircle(100, 15, 10, SSD1306_WHITE);
  // Рисуем закрашенный прямоугольник: (угол_X, угол_Y, ширина, высота, цвет)
  display.fillRect(90, 40, 30, 15, SSD1306_WHITE);

  // --- ВСЁ ПОДГОТОВЛЕНО, ПОКАЗЫВАЕМ НА ЭКРАНЕ ---
  // До этой команды всё "рисуется" в невидимой памяти (буфере)
  display.display();
  // Теперь всё появилось на экране!

  Serial.begin(9600);
  Serial.println("Дисплей инициализирован!");
}

void loop() {
  // В этом базовом примере loop пустой.
  // Всё наше изображение статично и было нарисовано один раз в setup().
}
```

**🔍 Что должно произойти:**
После загрузки кода на экране должны появиться надписи "Hello, Arduino!" и "OLED Rulez!", а также круг и прямоугольник в правой части экрана. В Мониторе порта должно быть сообщение "Дисплей инициализирован!".

### 🧠 **Разбор кода: Сравниваем C++ и Python**

Давайте посмотрим на ключевые моменты в коде и как они соотносятся с тем, что ты уже знаешь из Python.

| Концепция | В C++ (Arduino) | В Python (гипотетически) | Пояснение |
| :--- | :--- | :--- | :--- |
| **Подключение библиотек** | `#include <Library.h>` | `import library` | Почти одинаково. Библиотеки дают новые возможности. |
| **Объекты и классы** | `Adafruit_SSD1306 display(...);` | `display = SSD1306(...)` | `display` — это объект, созданный из класса `Adafruit_SSD1306`. С ним мы работаем через точку: `display.метод()`. |
| **Константы** | `#define SCREEN_WIDTH 128` | `SCREEN_WIDTH = 128` | `#define` создаёт константу. Вместо `SCREEN_WIDTH` компилятор везде подставит 128. В C++ есть и `const int`. |
| **Условие с выводом ошибки** | `if(!display.begin(...)) { ... }` | `if not display.begin(...):` | `!` означает логическое НЕ. `while(true);` — это бесконечный пустой цикл, он **останавливает** программу. Аналог в Python `while True: pass`. |
| **Методы работы с дисплеем** | `display.setCursor(0,0);` <br> `display.println("Text");` <br> `display.display();` | `display.set_cursor(0,0)` <br> `display.print("Text")` <br> `display.show()` | Принцип один: установить позицию -> написать -> отобразить. Имена функций часто совпадают. |
| **Статичная программа** | Вся отрисовка в `setup()` | Вся отрисовка в основном блоке кода | Часто для статичного изображения достаточно выполнить код один раз, а не в бесконечном цикле. |

**Главный вывод:** Библиотеки в Arduino скрывают сложность. Ты не работаешь напрямую с пикселями или I2C-протоколом, а используешь удобные функции высокого уровня, очень похожие на те, что могли бы быть в Python.

    *   Кнопками увеличивай/уменьшай минуты и секунды.

### 🆘 **Скорая помощь: если что-то пошло не так...**

*   **Экран не включается, ничего не видно:**
    *   **Проверь питание (VCC и GND)!** Самый частый случай. Пошевели провода.
    *   Попробуй подключить VCC к **5V**, если был в 3.3V (и наоборот).
    *   Покрути **контрастность**. У некоторых дисплеев есть маленький синий потенциометр сбоку.
*   **В Мониторе порта ошибка "Дисплей не найден!":**
    *   Проверь соединения **SDA (A4)** и **SCL (A5)**. Они легко перепутаются.
    *   Попробуй заменить адрес `0x3C` на `0x3D` в строке `display.begin(...)`.
    *   Убедись, что библиотеки **Adafruit SSD1306** и **Adafruit GFX** установлены.
*   **На экране мусор, полосы или изображение "плывёт":**
    *   Обычно это плохой контакт. Аккуратно переподключи все провода, особенно SDA и SCL.
    *   Попробуй добавить **подтягивающие резисторы** на 4.7 кОм между линиями SDA/SCL и питанием +5V.
*   **Код проекта не компилируется (ошибки с DHT11 и т.д.):**
    *   Установи нужные библиотеки (для DHT11, для ультразвука и т.п.).
    *   Внимательно читай ошибку компилятора. Часто он прямо указывает на строку с проблемой.
    *   Проверь, не забыл ли ты точку с запятой `;` в конце строк.
