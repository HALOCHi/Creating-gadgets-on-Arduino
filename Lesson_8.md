### **Занятие 8: Аналоговый джойстик — сердце игрового контроллера**

🎯 **Цель занятия:**
Создать свой собственный игровой контроллер! Научимся считывать положение ручки джойстика по двум осям (X и Y) и состояние кнопки. Соединим джойстик с OLED-дисплеем, чтобы создавать интерактивные проекты с визуальным откликом.

---
```cpp
// Пины для подключения джойстика
const int pinJoyX = A0;  // Ось X
const int pinJoyY = A1;  // Ось Y
const int pinButton = 2; // Кнопка джойстика

// Переменные для хранения значений
int xValue = 0;
int yValue = 0;
bool buttonState = false;

void setup() {
  Serial.begin(9600);
  
  pinMode(pinButton, INPUT_PULLUP); // Включаем внутренний подтягивающий резистор для кнопки
}

void loop() {
  // Чтение значений с аналоговых осей
  xValue = analogRead(pinJoyX);
  yValue = analogRead(pinJoyY);
  
  // Чтение состояния кнопки (инвертированное, так как используется INPUT_PULLUP)
  buttonState = !digitalRead(pinButton); // true - нажата, false - не нажата
  
  // Вывод значений в монитор порта
  Serial.print("X: ");
  Serial.print(xValue);
  Serial.print(" | Y: ");
  Serial.print(yValue);
  Serial.print(" | Button: ");
  Serial.println(buttonState ? "PRESSED" : "NOT PRESSED");
  
  delay(200); // Небольшая задержка для стабильности чтения
}
```

### 📖 **Теоретическая часть: Анатомия джойстика**

**1. Что внутри джойстика?**
Разбери джойстик в руках. Ты увидишь:
*   **Два потенциометра (переменных резистора):** Один отвечает за движение по оси **X** (влево-вправо), второй — по оси **Y** (вверх-вниз). Когда ты двигаешь ручку, меняется сопротивление этих потенциометров.
*   **Кнопка:** Нажимается, когда ты толкаешь ручку **вниз** (как на геймпаде — L3/R3).

**2. Как Arduino понимает положение?**
Джойстик — это **два аналоговых входа (X, Y) и один цифровой вход (кнопка)**.
*   **Аналоговые оси:** Arduino считывает напряжение с каждого потенциометра с помощью `analogRead()`. Значение будет в диапазоне **0-1023**.
    *   **0** — максимальное отклонение **влево** (для X) или **вниз** (для Y).
    *   **~512 (около 500)** — **центральное положение**.
    *   **1023** — максимальное отклонение **вправо** (для X) или **вверх** (для Y).
*   **Цифровая кнопка:** Работает как обычная кнопка. Чаще всего она **замыкается на GND при нажатии**, поэтому используем `INPUT_PULLUP` и считываем `LOW` как нажатое состояние.

**3. Уровни покоя (Dead Zone)**
В реальности, когда джойстик отпущен, значения редко бывают ровно 512. Они могут "плавать" (например, 505-520). Это нормально. Для создания устойчивых проектов (чтобы персонаж не шевелился сам по себе) мы введем понятие **"мертвой зоны"** — небольшого диапазона вокруг центра, который мы считаем "нулевым" положением.

**4. Подключение**
У джойстика обычно 5 выводов:
*   **GND** — Земля.
*   **+5V** — Питание.
*   **VRx** — Выход потенциометра по оси X → **подключаем к А0**.
*   **VRy** — Выход потенциометра по оси Y → **подключаем к А1**.
*   **SW** — Вывод кнопки → **подключаем к цифровому пину (например, D2)**.

**🔌 Собираем схему**
Подключи джойстик по следующей схеме:

```
        Джойстик (вид сверху, контакты в ряд)      ARDUINO UNO
        ------------------------------------      -----------
        |  GND  |  +5V  |  VRx  |  VRy  | SW |    |         |
        ------------------------------------      -----------
           |        |        |        |      |        |
           |        |        |        |      |        |
           |        |        |        |      |        |--> D2 (цифровой пин 2)
           |        |        |        |      |            (для кнопки с PULLUP)
           |        |        |        |      |
           |        |        |        |------|---------> A1 (аналоговый пин 1)
           |        |        |        |
           |        |        |-----------> A0 (аналоговый пин 0)
           |        |
           |--------|---------------------> 5V (питание)
           |
           -------------------------------> GND (земля)
```

**💻 Код: "Монитор состояния джойстика"**
Этот код будет считывать все параметры джойстика и выводить их в Монитор порта в удобном формате. Мы также введем "мертвую зону".

```cpp
// Объявляем пины для джойстика
const int pinJoyX = A0;   // Ось X подключена к A0
const int pinJoyY = A1;   // Ось Y подключена к A1
const int pinJoyBtn = 2;  // Кнопка подключена к D2

// Переменные для хранения значений
int joyX = 0;
int joyY = 0;
bool joyBtnState = false; // false - не нажата, true - нажата
bool lastBtnState = false; // Для обнаружения нажатия (по фронту)

// Настраиваем "мертвую зону". Значения в центре +- этого числа будут считаться "центром"
const int DEAD_ZONE = 50;

void setup() {
  // Инициализируем последовательное соединение
  Serial.begin(9600);

  // Настраиваем пин кнопки как вход с подтяжкой к +5V
  pinMode(pinJoyBtn, INPUT_PULLUP);

  // Пины A0 и A1 по умолчанию являются входами, настраивать не нужно

  Serial.println("=== ДИАГНОСТИКА ДЖОЙСТИКА ===");
  Serial.println("X\tY\tКнопка\tДействие");
  Serial.println("-----------------------------");
}

void loop() {
  // 1. Считываем "сырые" аналоговые значения
  int rawX = analogRead(pinJoyX);
  int rawY = analogRead(pinJoyY);

  // 2. Применяем "мертвую зону"
  // Если значение в пределах центра +- DEAD_ZONE, приравниваем к 512 (центру)
  if (abs(rawX - 512) < DEAD_ZONE) rawX = 512;
  if (abs(rawY - 512) < DEAD_ZONE) rawY = 512;

  // 3. Преобразуем диапазон 0-1023 в более удобный -100..0..+100
  // Это классическое представление для джойстиков
  joyX = map(rawX, 0, 1023, -100, 100);
  joyY = map(rawY, 0, 1023, -100, 100);
  // Инвертируем ось Y, чтобы "+" был вверх (по умолчанию 0 - вверх, 1023 - вниз)
  joyY = -joyY;

  // 4. Считываем состояние кнопки (с подтяжкой -> нажатие = LOW)
  bool currentBtnState = !digitalRead(pinJoyBtn); // Инвертируем: true = нажата

  // 5. Определяем "нажатие" (кнопка только что была отпущена и нажата)
  if (currentBtnState && !lastBtnState) {
    // Кнопку только что нажали
    Serial.println("КНОПКА НАЖАТА!");
  }
  lastBtnState = currentBtnState; // Запоминаем состояние для следующего цикла

  // 6. Выводим все данные в Монитор порта
  Serial.print(joyX);
  Serial.print("\t");
  Serial.print(joyY);
  Serial.print("\t");
  Serial.print(currentBtnState ? "ДА" : "НЕТ"); // Тернарный оператор: условие ? если_да : если_нет
  Serial.print("\t");

  // 7. Простая текстовая интерпретация направления
  String direction = "ЦЕНТР";
  if (joyY > 30) direction = "ВНИЗ";
  if (joyY < -30) direction = "ВВЕРХ";
  if (joyX > 30) direction = "ВПРАВО";
  if (joyX < -30) direction = "ВЛЕВО";
  // Комбинации (по диагонали)
  if (joyY > 30 && joyX > 30) direction = "ВНИЗ-ВПРАВО";
  if (joyY > 30 && joyX < -30) direction = "ВНИЗ-ВЛЕВО";
  if (joyY < -30 && joyX > 30) direction = "ВВЕРХ-ВПРАВО";
  if (joyY < -30 && joyX < -30) direction = "ВВЕРХ-ВЛЕВО";

  Serial.println(direction);

  delay(100); // Небольшая задержка, чтобы не захламлять монитор
}
```

**🔍 Что делать после загрузки кода:**
1.  Открой **Инструменты -> Монитор порта** (Ctrl+Shift+M).
2.  Убедись, что скорость (baud rate) выставлена **9600**.
3.  Подергай джойстик во все стороны, нажми на кнопку.
4.  Наблюдай, как меняются значения. В центре должны быть нули (или близкие к нулю). При движении — значения от -100 до 100.

### 🧠 **Разбор кода: Ключевые концепции C++ для игр**

**1. Функция `map()` для преобразования диапазонов**
`joyX = map(rawX, 0, 1023, -100, 100);`
Это золотая функция! Она переводит значение из одного диапазона в другой. Здесь мы превращаем "сырое" значение 0-1023 в игровое -100..0..+100, где 0 — центр.

**2. Константы и "мертвая зона"**
`const int DEAD_ZONE = 50;`
`const` создает **константу** — переменную, которую нельзя изменить в ходе программы. Это хороший стиль: "магические числа" (как 50) выносим в именованные константы в начале кода.

**3. Функция `abs()` — модуль числа**
`if (abs(rawX - 512) < DEAD_ZONE)`
`abs()` возвращает абсолютное значение (модуль) числа. Нам нужно проверить, **насколько** значение отличается от центра (512), независимо от того, в какую сторону.

**4. Обнаружение нажатия кнопки (обработка по фронту)**
Мы храним два состояния кнопки: `currentBtnState` (текущее) и `lastBtnState` (предыдущее).
*   **Нажатие** определяется условием `if (currentBtnState && !lastBtnState)` — сейчас нажата, а в прошлый раз была не нажата.
*   Это позволяет среагировать **один раз** на одно нажатие, даже если в цикле `loop()` кнопка будет считаться нажатой много раз подряд.

**5. Тернарный оператор `? :`**
`Serial.print(currentBtnState ? "ДА" : "НЕТ");`
Это компактная замена `if-else`. Читается так: **если** `currentBtnState` **истинно**, то `"ДА"`, **иначе** `"НЕТ"`.

*   **Совет:** Для отображения точки нужно преобразовать диапазон -100..100 в координаты экрана 0..127 и 0..63 с помощью двух функций `map()`.

*   **Цель:** Создать простую графическую игру.
*   **Что нужно:** Схема **джойстик + OLED**.
*   **Задача:**
    1.  Управляй **квадратиком-персонажем** (5x5 пикселей) с помощью джойстика.
    2.  На экране в случайных местах появляются **"звёзды"** (точки). При соприкосновении (коллизии) персонажа со звездой:
        *   Звезда исчезает.
        *   Счет увеличивается на 1.
        *   Звезда появляется в новом случайном месте.
    3.  Выводи **счет** вверху экрана.
    4.  **Усложнение:** Добавь врагов (движущиеся точки), которых нужно избегать. При столкновении счет обнуляется.
*   **Совет:** Для случайных чисел используй `random(min, max)`. Для обнаружения столкновения проверяй, что координаты персонажа и звезды отличаются не более чем на N пикселей.

**🔹 Проект 3: “Управление сервоприводом с визуальной обратной связью”**
*   **Цель:** Связать механику (сервопривод) с графическим интерфейсом.
*   **Что нужно:** Схема **джойстик + OLED + Сервопривод SG90** (вспомни занятие 5).
*   **Задача:**
    1.  Ось X джойстика управляет **углом поворота сервопривода** (от 0° до 180°).
    2.  На OLED-экране:
        *   Рисуй **шкáлу** от 0 до 180 градусов.
        *   Рисуй **стрелку** или **ползунок**, положение которых соответствует текущему углу.
        *   Выводи цифровое значение угла.
    3.  **Кнопка джойстика** — это "замок". Пока кнопка нажата, сервопривод удерживает текущий угол. Когда отпускаешь, серво возвращается в центральное положение (90°).
    4.  Ось Y можно использовать для управления **скоростью** движения сервы (медленно/быстро).
*   **Совет:** Не забудь, что сервоприводу нужно питание от отдельного источника (или от Arduino через внешний блок). Управляющий сигнал подай на любой цифровой пин, например, D9.

### ❓ **Вопросы на засыпку**

1.  Почему для кнопки джойстика мы используем `INPUT_PULLUP` и инвертируем логику (`!digitalRead()`), а не просто `INPUT`? Что произойдет, если подключить кнопку без подтяжки?

3.  В коде мы инвертировали ось Y (`joyY = -joyY`). Почему это пришлось сделать? Как было бы удобнее подключить джойстик изначально?

5.  Как бы ты организовал управление в игре, если нужно **одной кнопкой** выполнять разные действия? Например, короткое нажатие — прыжок, длинное удержание — приседание. Предложи алгоритм.

### 🆘 **Скорая помощь: если что-то пошло не так...**

*   **Значения в мониторе порта не меняются или всегда 0/1023:**
    *   **Перепроверь подключение аналоговых пинов A0 и A1!** Самые частые ошибки: перепутаны VRx и VRy, или они подключены к цифровым пинам.
    *   Проверь питание джойстика (+5V и GND).
*   **Значения "скачут" даже когда джойстик не трогаешь:**
    *   Это нормальный небольшой шум. Увеличь значение `DEAD_ZONE` в коде (например, до 80 или 100).
    *   Проверь, все ли провода надежно воткнуты в макетную плану.
*   **Кнопка не работает или срабатывает сама по себе:**
    *   Проверь, что пин кнопки (`pinJoyBtn`) объявлен как `INPUT_PULLUP`.
    *   Проверь подключение вывода `SW` джойстика. Он должен идти **только на цифровой пин Arduino**, больше никуда.
*   **При подключении OLED и джойстика вместе что-то не работает:**
    *   Помни: OLED использует пины **A4 (SDA)** и **A5 (SCL)**. Джойстик использует **A0, A1** и цифровой пин (например, D2). Они **не конфликтуют**.
    *   Проверь, хватает ли питания. Если используешь много компонентов, попробуй запитать Arduino от блока питания, а не от USB.
*   **Сервопривод дергается или не слушается джойстика:**
    *   **Питание!** Сервопривод "кушает" много тока. Питай его от отдельного источника 5V или через мощный внешний блок. Пин **GND** внешнего источника и Arduino **должны быть соединены**.
    *   В коде не пытайся обновлять угол сервы слишком часто. Достаточно обновлять раз в 50-100 мс.
